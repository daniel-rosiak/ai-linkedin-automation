## Problem Statement

Professionals in the software engineering and AI space need to maintain an active, authoritative presence on LinkedIn by sharing high-quality, technical insights. However, the process of manually curating daily news from diverse technical sources, synthesizing the information, drafting an engaging post, and creating a visually appealing accompanying graphic is highly time-consuming. Fully automated tools often miss the user's specific tone or preferred topics, leading to generic or off-brand posts. The user needs a system that does the heavy lifting of curation and generation but keeps the human in the loop for final approval, preferably accessible on-the-go via a mobile device.

## Solution

A Python-based Telegram bot that acts as an AI LinkedIn Post Generator. The bot fetches top daily articles from sources like Hacker News, GitHub Trending, and ArXiv. Using either Google Gemini or a local Ollama model, it generates 3-5 distinct LinkedIn post proposals and sends them to the user via Telegram. The user can review these proposals on their phone and use interactive buttons to Approve or Reject them. The system learns from rejections to improve future proposals. Upon approval, the bot generates the full post text and uses a headless Playwright browser to render a beautiful, Tailwind CSS-styled graphic, delivering the final assets directly back to the user's Telegram chat for easy copy-pasting to LinkedIn.

## User Stories

1. As a user, I want to send a command (e.g., `/generate`) to my Telegram bot, so that I can trigger the daily news curation and proposal process on demand.
2. As a user, I want the bot to fetch the top current articles from Hacker News, GitHub Trending, ArXiv, and Reddit, so that I have a diverse pool of high-quality technical content to choose from.
3. As a user, I want the system to filter out articles it has already proposed to me in the past, so that I don't waste time reviewing duplicate content.
4. As a user, I want the bot to present 3 to 5 distinct LinkedIn post proposals in my Telegram chat, so that I have multiple options and angles for my daily post.
5. As a user, I want each proposal message to have interactive `[Approve]`, `[Reject]`, and `[Skip]` buttons, so that I can easily make decisions directly within the Telegram UI.
6. As a user, I want my rejected proposals to be saved in a database, so that the AI can use them as negative constraints in future prompts and learn my preferences.
7. As a user, I want my approved proposals to be saved in a database, so that the AI can use them as positive examples to generate content more aligned with my tastes.
8. As a developer, I want to configure the AI provider via an environment variable (`LLM_PROVIDER`), so that I can easily switch between Google Gemini and a local Ollama model.
9. As a user, I want to use a local Ollama model (like Llama 3), so that I can run the generation entirely locally without incurring API costs or sharing data externally.
10. As a user, I want to use Google Gemini, so that I can leverage a highly capable, fast, and structured LLM for post generation.
11. As a user, I want the bot to automatically generate a beautiful, modern graphic using Tailwind CSS and Playwright when I approve a post, so that my LinkedIn content stands out visually.
12. As a user, I want the bot to send the final generated Markdown text and the rendered PNG image back to my Telegram chat, so that I can easily save the image and copy the text to publish on LinkedIn.
13. As a user, I want the Telegram bot to strictly enforce an `ALLOWED_CHAT_ID` check, so that unauthorized individuals cannot interact with my bot, access my data, or consume my API quota.

## Implementation Decisions

- **Application Interface**: The primary interface will be a Telegram Bot using `python-telegram-bot`, utilizing long-polling or webhooks.
- **Storage Strategy**: A local SQLite database (`history.db`) will be used to track all fetched URLs, proposals, and their statuses (`approved`, `rejected`, `skipped`).
- **LLM Abstraction**: The AI integration will use an Abstract Base Class (Provider) pattern to ensure the core application logic remains agnostic to whether Gemini or Ollama is being used.
- **AI Learning Loop**: The proposal generation prompt will dynamically inject recent `approved` and `rejected` angles fetched from the SQLite database to guide the LLM's output.
- **Graphics Rendering Engine**: Visuals will be generated by using Playwright to open a local HTML template. The template will use Tailwind CSS via CDN. The Python script will inject the generated title and subtitle into the DOM before taking a screenshot.
- **Security**: A decorator/middleware function will be implemented on all Telegram command and callback handlers to immediately reject updates that do not match the configured `ALLOWED_CHAT_ID`.

## Out of Scope

- **Direct LinkedIn API Posting**: The application will not authenticate with or post directly to the LinkedIn API. It functions strictly as a draft/asset generator (Draft Mode).
- **Multi-User Support**: The bot is designed for a single user/owner. Features like user registration, role-based access control, or handling multiple users with distinct learning profiles are out of scope.
- **Complex Database Migrations**: As a lightweight personal tool, if schema changes are required, the user can manually drop and recreate the SQLite database. Automated migration scripts (e.g., Alembic/Flyway) are out of scope.
- **Cloud Infrastructure Deployment**: The tool is built to run locally (especially to support Ollama and Playwright). Cloud deployment configurations (Dockerfiles for AWS/GCP, Terraform) are out of scope.

## Further Notes

- Prompts tailored for Ollama may need stricter formatting instructions (like forcing JSON schemas) compared to Gemini, which natively handles structured output well. The LLM provider implementations should handle their own prompt formatting specific to the model's strengths.
- The Playwright installation will require the user to run `playwright install chromium` locally before the graphics engine can function.
